Depth-guided light

Run the vendored depth model on the CC0 still-life sample, then move a light across its estimated surface. Both modes derive normals and reject boundaries from depth alone. Photo colors already contain lighting; this modulates them rather than recovering albedo or removing shadows.

Analytic check: original CC0 spheres, floor, and wall, made by Ryan with Codex (GPT-6). Reference normals are used only to measure error, never to select pixels.

      Photo mode calls estimateDepth with the existing 27,258,801-byte int8 ONNX model
      and ONNX Runtime Web WASM worker. The model loads from this repository only after Run photo
      depth; no new weights, remote requests, or uploads. Repeated runs reuse the worker until this
      page closes.
    

    

      Memory lists live page arrays, estimated canvas backing, and the worker's retained input
      tensor. Serialized model bytes are listed separately and in an accounted minimum. ORT
      session/activation tensors, WASM heap, transient copies, scratch/GC, image decoding, and
      compositor memory are unmeasured; this is not process peak. Times end at canvas submission,
      not display presentation.
    

    

      Photo geometry is a guess: inverse depth is normalized at its 2nd/98th percentiles, mapped to
      inverse distances 1/8 through 1/2, then inverted to camera Z. Near/far 2–8 and focal length
      0.8 × the long side are assumptions, not metric depth or a recovered camera. Smooth depth
      errors, boundary halos, baked shadows, cast shadows, and hidden surfaces remain unresolved.
