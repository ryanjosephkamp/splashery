What changed in this phase

The first prototype played character frames and offered media created beforehand. This one captures fresh source motion and includes reusable GIF and video encoders. A changed color or detail setting now changes the file you create.

Grapes and orange wedges keep recognizable motion. The strawberry’s outline survives better than its small seeds and texture; color helps separate its regions. These three examples establish a working path, not compatibility with every toy.

GIF timing uses cumulative rounding to its centisecond timeline. Browser video uses real-time recording and can vary with the device; the prototype stops if it falls behind. The owner reported that this prototype passes their device review on October 6, 2026. The device and browser were not specified.

Technical handoff and sources

Capture: isolated page, fixed home camera, manually stepped simulation, 40 lossless 420 × 420 PNG frames per toy at 10 fps. The adapter restores the render controls it changes on success, failure, and cancellation. Its page is then closed; simulation effects are not rewound inside an existing live toy. The portable demo uses 210 × 210 area-averaged PNG derivatives; full-size captures stay in the preserved local source ZIP. This repository package retains the portable inputs and capture receipts.

Exports use the exact ASCII core from PR #335. GIF uses the already installed gifenc 1.0.3 under its MIT license. Video uses the browser’s MediaRecorder format support and canvas capture. No camera or microphone is requested.
