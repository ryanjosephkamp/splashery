# Phone and accessibility audit — October 2, 2026

- Chess moves and individual piano notes lack keyboard access.
- At 844×390, all six panel panes collapse to 20 px of padding.
- The embed canvas ignores the keyboard; its zoom buttons work.
- Phone zoom needs two fingers; controls miss the 44×44 target.
- Help disappears after seven seconds, even with focus inside it.
- Escape from text fields fails; closing sheets also loses focus.
- Empty searches are not announced; desktop toy names are clipped.
- All 30 sampled how-to lines fit; basic Play works with one finger.
- Inspected names, contrast, and reduced motion on load passed.

Task 52 rechecked this historical audit on October 13, 2026. The **Fixed in task 52** column records
each finding's current status; the recheck, evidence, and verification are below.

## Scope and method

Codex built this audit against `main` commit `2ec27c1568cdd496f6fc9d8416be8b5049ee4fe5`, on
`codex/phone-a11y`. Only this report and its PNG screenshots are deliverables; the UI lane makes
fixes. The shared checkout was switched to another audit branch during the run, so the outputs were
moved to an isolated checkout of this branch. The served application files remained identical to the
frozen `main` baseline.

The local server was `python3 -m http.server 4173 --bind 127.0.0.1`. The installed Playwright 1.56.1
drove Chromium through the system Chrome executable, version 154.0.8037.95. Phone contexts used
390×844 CSS pixels, touch, mobile emulation, and device scale factor 3; desktop contexts used
1440×900. Landscape was 844×390 with the phone context, including a fresh context to rule out saved
panel sizes. Labs stayed off for the initial public audit; a separate pass used `?labs=1`. The final
public gallery check used `?labs=0`, because the switch persists in local storage. `?help=show` was
used on some pages to expose the normal automatic help line that this application deliberately
suppresses under browser automation (`src/ui.js:2599`). The 30-line fit check explicitly opened the
help line.

Checks used actual Playwright keyboard input, single touch points, DOM bounding boxes, computed
styles, `page.accessibility.snapshot({ interestingOnly: false })`, and `locator.ariaSnapshot()`.
Screenshots are at CSS pixel resolution; large desktop shots are unscaled crops of the relevant
area, with the viewport still 1440×900. All original October 2 PNG files are under 300,000 bytes. A
screenshot documents the visual state; the accompanying keyboard or accessibility-tree observation
establishes a nonvisual problem.

Priorities: **P1** blocks an important activity; **P2** needs a UI fix; **P3** is a usability
improvement. WCAG references below identify the applicable criterion or explicitly mark a concern.
This is an audit of the inspected surface, not a WCAG conformance certification. The task's 44×44
goal is also
[2.5.5 Target Size (Enhanced), AAA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html);
[2.5.8 Target Size (Minimum), AA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
uses 24×24 with exceptions and a spacing alternative. A 32×32 button is therefore a task-target
failure, not automatically an AA failure.

### Keyboard and accessibility tree

Main-stage ArrowRight and `+` changed camera yaw/distance. Enter on Play fired the toy action.
Tab/Shift+Tab, Enter/Space on buttons, and native select/range arrows worked in the inspected
controls. Tab-list ArrowRight/ArrowLeft, Home, and End select the corresponding panel and move
focus. Focus uses a visible 2 px accent outline (`styles.css:104`); the normal visible-control
outlines were distinguishable. F1, F3, F5–F7, and F12 describe the exceptions and transition
problems.

The full accessibility snapshots of all six public panes and the labs examples contained names for
the inspected native buttons, switches, ranges, inputs, and selects. The banner, heading, named
complementary controls landmark, named shelf navigation, tab list, and tab panels form a readable
structure. There is no main landmark for the stage; its canvas is exposed as one image. The
snapshots establish structure and names, not actual speech or successful screen-reader play.

Representative observed tree entries:

```text
img "Cactus, a toy made of 450k splats. Drag to turn it ..."
button "How to play"
group "Play with the toy": button "Play", button "Hands-on"
complementary "Splashery controls"
navigation "Toy shelf"
tablist "Controls": tab "Toy", tab "Tools", tab "Look", ...
```

Toy-loaded text updates `#toy-status[aria-live=polite]`; the recording pill and export/copy toast
have live status roles; input failures expose `role=alert`. The empty search status is the missing
announcement in F8. Recording's live clock updates each second; whether that is excessively chatty
needs a real reader. The CNN pad has an accessible label but is not focusable (`tabIndex=-1`) and
has no keyboard cell editor. Its text/file input offers another input route; no blanket keyboard
failure is claimed for essential freehand drawing. A single-finger stroke submitted a custom digit
successfully. [Pad](phone-a11y-2026-10/27-phone-drawing-pad.png).

### Motion, sound, and live input

A fresh reduced-motion context reported `reducedMotion=true`, `motionAllowed=false`, effective
motion `{ alive: false, move: "still" }`, turntable off, and its toggle disabled. CSS
transitions/animations are removed under the preference (`styles.css:1922`); the site's automatic
motion and turntable are suppressed (`src/player.js:1181`, `src/player.js:1348`). Changing the
system preference after load was not evaluated. Explicitly requested toy animation is separate from
automatic motion.

Before any visitor gesture, instrumentation saw zero AudioContext constructions, zero media-device
requests, and no playing audio/video elements in the fresh labs context. Merely opening the seven
labs examples added no media requests or audio contexts. The microphone and camera buttons state
what they use and show the on-device/no-recording note before the request. Only tapping each button
invoked `getUserMedia`, with the appropriate microphone or camera constraints. A denial stub
returned a named, readable alert; real devices and real permission prompts were not opened.
[Microphone](phone-a11y-2026-10/18-labs-room-echo.png),
[camera](phone-a11y-2026-10/18-labs-splat-mirror.png),
[desktop screen-share preface](phone-a11y-2026-10/34-labs-screen-desktop.png). This confirms the
inspected request timing, not every platform's audio or capture behavior.
