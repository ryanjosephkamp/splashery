## Measurements

[measurements.json](measurements.json) records each clip's state, readiness, rendered frames, timing
percentiles, resource entries, and page-script errors. The run used Chromium 151.0.7922.173,
Playwright 1.56.1, Node 24.19.0, a mobile user agent, touch, DPR 1, forced mid profile, WebGL2, and
SwiftShader. No CPU or network throttling was applied. These are software-renderer cloud results,

Readiness begins at `chooseToy()` after the shell is ready. The moving clip also waits for Sharp
picture visibility. The mirror's ready time precedes Start camera; camera start to three accepted
answers was 1.16 s. At the later measurement snapshot its current depth object reported three
accepted answers, one discarded result, and a last model inference time of 507.6 ms. These sparse
observations do not establish sustained depth-update cadence or capture latency. The camera stream
is generated by the existing `tools/cdx-mir-camera.mjs` and `tools/lv7-mannequin.mjs`, at 320×240
and 15 fps, then sent through the real worker.

Render rate counts the stage's `postrender` events during a six-second window, after warm-up and
before screencast capture. The resting model receives a forced render window. `transferBodyBytes`
sums same-origin main-document resource timing body sizes, including shell resources; it excludes
main HTML and worker-only downloads and is **not total transfer**. `sharp.cost` is the relief's
estimated texture/mesh allocation, not total tab memory. Offline fitting statistics in the video
state describe the existing baked sample, not newly measured training.

No new local GIF inference, long-video completion, custom WebGPU reconstruction, physical camera,
microphone, real-phone thermals, or peak tab memory was measured. Only one representative display
clip per toy was captured.

## Reproduce the capture

Keep the saved production snapshot immutable. Use an isolated detached worktree, existing npm
dependencies, and an existing Chromium; do not install a browser:

```sh
git worktree add --detach /tmp/toy-checkpoints-b-run 41b21e74e04ccca178b95ac02b4e5dc0e51b4b45
cd /tmp/toy-checkpoints-b-run
mkdir -p .cache/checkpoint-b
# Copy this evidence's capture.mjs to .cache/checkpoint-b/capture.mjs.
# Provide node_modules from the prepared environment, or run npm ci.
python3 -m http.server 4173 --bind 127.0.0.1
```

Run the following in a second shell in that worktree:

```sh
SPLASHERY_CHROMIUM=/usr/bin/chromium node .cache/checkpoint-b/capture.mjs
```

The script must run from `.cache/checkpoint-b/`'s file location because its ES module imports
resolve relative to that location. It writes timestamped JPEG frames, concat lists, screenshots, and
measurements under `.cache/checkpoint-b/`. It skips a toy already present in `measurements.json`;
remove that local JSON to start a fresh measurement run. Timing and captured frame counts vary
between runs.

Encode each of the four recorded sequences from the repository root:

```sh
ffmpeg -f concat -safe 0 -i .cache/checkpoint-b/moving-photo-3d/frames.txt -vf scale=390:844 -r 15 -c:v libx264 -crf 23 -pix_fmt yuv420p -movflags +faststart moving-photo-3d-390x844.mp4
```

Replace the toy ID with `video-3d`, `splat-mirror`, or `model-splats` for the other sequences.
Capture and conversion tooling stays on this evidence branch.
