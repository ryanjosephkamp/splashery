# Pictures to objects: what to add

October 17, 2026. Research and recommendations: **Codex (GPT-6)**. Task 117; report only.

**Add, in order: promptable masks, DA3 Small camera initialization, and a TripoSR draft mesh.** Keep
the agent-built kit or Blender model as the editable result. PartCrafter is the most useful next GPU
experiment for movable furniture parts; TRELLIS.2 and Pixal3D need license exceptions in their
current pipelines. These are recommendations, not measured integration results.

## Evidence and reading the table

Live primary sources, licenses, model cards, inference scripts, and checkpoint metadata were opened
on the date above. No model inference, two-object reconstruction test, Mac test, or browser port was
run. The quality evidence below is published evaluation, with its dataset and limitations
identified. **NR** means not established by the opened sources; it is not an estimate of zero cost.

**C** = Linux cloud CPU, **A** = Apple silicon, **G** = NVIDIA CUDA GPU. “Path” means source code or
documentation offers that route, not that it was tested here. **No native browser inference was
verified for any learned 3D generator in this table.** A Gradio or hosted demo is a server
interface. Unless a row gives a C/A time, that time is NR; GPU timings cannot be substituted for it.
Times exclude installation, downloads, queues, and export unless the source explicitly includes
them.

**P** = no additional output-use restriction found in the cited permissive release; input rights
still apply. It does not establish copyright ownership or make an output CC0. **T** = conditions
apply; **U** = output reuse is unresolved. NC model or code licensing does not by itself establish
the license of generated geometry. Eligibility requires both code and weights to pass task 117's
Apache-2.0/MIT/BSD rule, plus a check of dependencies; a repository badge alone is insufficient.
Sizes are decimal checkpoint bytes rounded to GB/MB, or published parameter counts/VRAM; they are
not download budgets for an entire environment. Weight links to Hub APIs include file metadata.

## What the furniture evidence establishes

- [PartCrafter, Table 1][partcrafter-paper]: ABO F-score at 0.1 is 0.8617 versus TripoSG 0.7096; L2
  Chamfer 0.1047 versus 0.2017. Table 2's indoor 3D-Front F-score is 0.8148, or 0.7800 on its
  occluded subset. The 34 s H20 timing is for four-part generation. These are useful household/scene
  proxies, not isolated thin-leg or glass measurements; its part-overlap IoU is not task 113's
  volume IoU against truth.
- [SAM 3D, Table 2][sam3d-paper]: SA-3DAO isolated-object volume IoU is 0.2311 versus TRELLIS 0.1392
  and Hunyuan3D-2.1 0.1266. This mixed in-the-wild benchmark supports its robustness claim, not a
  furniture-only ranking or passage of Splashery's gates.
- [Pixal3D, Tables 1 and 3][pixal-paper]: Toys4K normal-render IoU is 93.57 versus TRELLIS 79.48 and
  Hunyuan3D-2.1 83.33; multiview F-score rises from 64.94 at two views to 69.04 at six. These are
  the paper's model and protocol, not measured results for the newer TRELLIS.2-based branch; the
  [repository][pixal] distinguishes those versions.
- [TripoSR, Tables 2 and 3][triposr-paper]: F-score at 0.1 is 0.651 on GSO and 0.677 on
  OmniObject3D. This establishes a coarse household-object baseline, not exact slats. Different
  datasets, alignment, sampling, and thresholds prevent comparison to the numbers above.

**Engineering inference:** use a procedural slat/leg array when count and spacing matter; demand
visible negative space through every hole. Single-image generators complete backs from priors;
additional photographs constrain only what they show. Neither a plausible hidden back nor a PBR
opacity channel proves faithful glass geometry. Fit glass as an explicit material and surface in
Blender, and review it under a second background and viewpoint. No opened evaluation establishes
reliable transparent-furniture recovery. These judgments follow the ambiguity and limitations in
[Pixal3D][pixal-paper], [SPAR3D][spar3d-w], and [COLMAP's capture guidance][colmap-tutorial].

## What a modeling agent should copy

[BlenderGym][blendergym-paper] proposes alternative edits, renders them, and uses a verifier to
choose, including parameter tuning versus structural changes. Its human comparison and verifier
failure analysis argue for numerical checks as well as visual judgment. [LL3M][ll3m] adds a part
plan, Blender API retrieval, executable debugging, and visual critique; its shipped client is not an
available self-contained backend. [SEIG][seig-paper] separates geometry, materials, composition, and
lighting, with respective refinement budgets of five, three, three, and two rounds.

For task 114, implement that staging independently: freeze cameras after calibration, fit gray
geometry first, score all reference views, fix the worst part, then add materials and lighting. Keep
a best-so-far script, named parts/pivots, execution errors, renders, scores, and a hard budget.
Reject prettier renders that worsen silhouette/3D scores. This is a proposed extension to the
existing loop, not evidence that the published agents satisfy task 114. [BlenderLLM][blenderllm]
explicitly lacks image input and multi-turn interaction. [CAD-Recode][cadrecode] needs points;
[Cadrille][cadrille] accepts images but has NC weights. [Zero-to-CAD][zerotocad-w] reports mean IoU
0.747 on its synthetic test and 0.377 on out-of-distribution ABC, using eight clean rendered views
and rotational alignment; do not transfer that score to three store photographs.

## Three to add, with implementation and gates

1. **SAM 2.1 tiny plus original MIT BiRefNet masks.** Add an optional build-time mask proposal step
   to task 113, point/box selection and negative points for holes, then manual correction. Pin
   weights, hashes, and licenses; use CPU-capable inference with optional CUDA components disabled.
   Budget 156 MB for SAM or 444 MB for BiRefNet, excluding runtimes. **Proposed gate:** on two CC0
   truth objects (slatted chair and handled household object), three views each, silhouette IoU
   ≥0.95, correct hole/slat count in every view, and zero erased visible legs. Record cold/warm CPU
   wall time and peak RAM; require six masks within two minutes warm.
2. **Depth Anything 3 Small cameras, compared with MapAnything Apache and classical COLMAP.** Add a
   task 113 initializer importing intrinsics/extrinsics without silently recropping images; use
   listing dimensions to resolve scale. [DA3 Small][da3-small] is the first CPU pilot at 137 MB;
   Base is 542 MB. [MapAnything][mapanything] is a 4.91 GB comparison if the smaller model fails.
   Cache pinned weights outside git, make downloads opt-in, and audit compiled dependencies. Use
   classical SIFT for COLMAP validation. **Proposed gate:** the same six truth views, median
   rotation error ≤5°, median focal-length error ≤10%, and no mirrored/flipped cameras; matched-view
   silhouette IoU must improve or stay within 0.01 of manual cameras. Require three-view CPU
   initialization within two minutes warm and ≤8 GB peak RAM, or retain manual/CPU-SfM cameras.
   Runtime bounds are unmeasured. Never substitute DA3 Large/Giant or default NC MapAnything.
3. **TripoSR as an optional draft, followed by the kit/Blender correction loop.** Its
   [runner][triposr-run] explicitly falls back to CPU. Adapt a minimal pinned runner for already
   masked images, vertex-colored GLB, and controlled extraction resolution; bypass background
   downloads. Align its arbitrary-scale output to the pack, then rebuild moving parts as named
   objects. Budget 1.68 GB weights plus runtime. **Proposed gate:** compare against a cold kit start
   on those two CC0 three-view packs, hiding truth and cameras from builders. At the same 30-minute
   budget, require task 114's median silhouette IoU ≥0.90 and volume IoU ≥0.70, no lost holes, and
   lower time-to-gate; draft generation must finish within five minutes on the actual CPU. Log
   failure as a rejected seed, not a completed toy. If it fails, keep procedural initialization.

Each pilot must record hardware, threads, resolution, versions, download/install time, warm and cold
latency, peak RAM, and all input/output hashes. Repeat scoring within 0.5 points and check a
wrong-box control, as [tasks 113][task113] and [114][task114] require. Their full truth-pack gates
still apply after the two-object pilot. No site inference, visitor uploads, or new service is
needed.

## Few photographs, exclusions, and the next GPU experiment

For **3–10 actual overlapping views**, try classical SIFT/COLMAP for cameras first; keep original
framing and distinguish a fixed object with moving camera from a turntable/background mixture. The
[tutorial][colmap-tutorial] requires overlapping, textured, well-exposed images and warns about
specular surfaces. Three catalog angles with different crops, repeated slats, white upholstery,
glass, or unseen undersides may not constrain a complete mesh. This is an inference from those
capture requirements, not a measured 3–10-photo success rate. Use masks to exclude background,
listing dimensions for scale, and known/manual cameras when matching fails. DA3 and MapAnything can
propose geometry/cameras with fewer matches, but learned predictions are not independent
measurements. Do not feed a generator's invented views into evaluation as if they were captured
photographs.

The [COLMAP FAQ][colmap-faq] excludes dense reconstruction without CUDA; CPU SfM is still useful.
openMVG, openMVS, and AliceVision do not pass the requested license list. DUSt3R/MASt3R have NC and
dataset conditions; VGGT's commercial checkpoint still uses a custom license. This leaves no
verified turnkey Apache/MIT/BSD CPU pipeline here that guarantees a complete textured furniture mesh
from three catalog photos. Returning cameras/partial points and using task 114 is useful.

**License holds:** [Hunyuan 2.0][hunyuan2-license] and [2.1][hunyuan21-license] exclude the EU, UK,
and South Korea from their territory and restrict output use outside it; commercial scale also has
conditions. [SF3D][sf3d-license]/[SPAR3D][spar3d-license] impose community-license, registration,
revenue, and use conditions. [SAM 3D][sam3d-license] uses Meta's custom SAM License, not SAM 2's
Apache license, and requires [≥32 GB GPU][sam3d-setup]. None is approved by this survey.

**Pipeline holds:** TRELLIS.2's [config][trellis2-pipeline] and Pixal3D's [config][pixal-config]
load [custom-licensed DINOv3][dinov3-w] and [NC RMBG-2.0][rmbg2]. Changing only the background
remover does not clear DINOv3. [nvdiffrast][nvdiffrast-license] and [nvdiffrec][nvdiffrec-license]
also use NVIDIA source licenses outside the allowlist. LGM's [rasterizer][gaussian-license] is
separately restricted. TripoSG and PartCrafter [runners][triposg-inference]
[load][partcrafter-inference]
[noncommercial RMBG-1.4](https://huggingface.co/briaai/RMBG-1.4/resolve/main/README.md)
unconditionally, even when removal is not requested in PartCrafter; remove the load/import and
download, then audit remaining dependencies. A permissive core is not whole-stack approval.

**Next GPU experiment:** PartCrafter first, then TripoSG, with clean masks and no BRIA downloads.
PartCrafter's separate parts and household benchmarks are more relevant to animation than a single
fused surface. Require the same task 114 quality gate, correct part count/pivots, and solid-part
motion in clips; measure export and mesh-to-splat cost as well as generation. Both require an
optional GPU worker, not the ordinary CPU container or the browser. TRELLIS.2/Pixal3D wait for
explicit license exceptions or a verified alternative pipeline. Hosted services and multi-GB weights
never belong in the static page. This report adds no dependency, model, or asset.
