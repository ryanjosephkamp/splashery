# Exact-ceil HTML playback extraction research R2

Outside-only, phone-only diagnostic. No product, frozen runtime, five protocol modules, controller state, or native bake was changed. R1 evidence remains frozen separately. This code and original research are MIT, made by Ryan with Codex (GPT-6); frozen Splashery MIT frame/extraction/receipt helpers and the author's frozen MP4 parser are copied byte-for-byte and hash-bound in declaration.json. The saved photographs retain each original corpus source/license/author attribution in the result's inputBinding; the own-code MIT grant does not replace those media licenses.

The declaration predeclares all20 corpus IDs in manifest order, exact390×844/touch/UA/deviceScaleFactor1 benchmark context,16native phone windows (palace15),480longside,3trials/window, original fitSide/panoSafeCrop/sharpness/JPEG.92. Source PTS come from the frozen r2 ISO-BMFF tables, never WebCodecs. Three unsupported complex edit-list captures immediately fall back; no clip is silently omitted.

For every trial the algorithm calculates the exact first source PTS at/after the original requested time using integer/rational comparison. It requires rounded actual RVFC.mediaTime microseconds equal the desired frame; an intervening frame may be observed but a skipped desired frame, repeated/nonmonotonic actual PTS, crossed window, abort or deadline rejects the entire extraction. The returned best-of-three photo retains its actual RVFC time and requested target separately. No partial photograph array is returned on extraction failure.

Startup is uniform: one actual seek to min(.5,duration/4), wait for a presentation after seeked, warm the same HTML→2D draw/readback while paused, then at most one actual rewind to min(.001,firstDesired/4). A confirmed paused exact first source picture may be captured immediately; otherwise playback at1× begins from its confirmed PTS. There is no adaptive chasing, clip-specific preset, synthetic timestamp, WebCodecs decode, or picture alteration. On every accepted trial pause immediately in RVFC, copy pixels synchronously, encode if the original sharpness best changes, then resume. Per-video operation ownership prevents an old play fulfillment from pausing a later operation. The single reset is not the canonical helper's same-position cached path.

Every completed extraction is checked against a separately opened decoder using the unchanged frozen sourceFrameReceipts. Every saved JPEG SHA must equal the independently recreated and repeated JPEG; its independently matched sourceTime must equal recorded actual RVFC PTS within1µs. No held-out images are read. These receipts establish source-picture identity only; the copied receipt method's generic held-out wording is inapplicable because views/times are empty. No tolerance is allowed for JPEG bytes and no source-time relabeling occurs.

One owned Chromium151 browser uses unchanged frozen benchmarkLaunchArgs('swiftshader'); each case has a fresh exact mobile context. Capture abort90s, whole-case host context watchdog120s, collection14min. These are diagnostic watchdogs, not production budget proposals. All attempted/fallback costs and cleanup states are retained. Source videos are muted local files, no permissions/device/camera/network upload. Browser/server/contexts close after collection. Concurrent native corpus jobs remain running and untouched, so these are extraction measurements under shared software-GPU load, not physical-phone or isolated native bake timing evidence.

Run CPU controls: `node --test test.mjs`. Run the predeclared browser collection: `node probe.mjs` (one authorized run only). Summarize and independently recheck saved image/hash/trial bindings: `node summarize.mjs`. Raw all20 results, console log, every actual-RVFC/trial progress row, FFprobe source timestamps and source/license bindings are retained. R1 phone seek controls, where available, are historical1440×900-context measurements under a different load/time; they are not matched timing controls for R2's mobile context. No full corpus speed ratio is inferred from them.

Results and limitations are recorded in summary.json and the final freeze receipt. No production integration or acceptance is claimed from this experiment.
