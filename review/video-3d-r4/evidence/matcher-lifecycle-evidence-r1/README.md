# Exact matcher chunks and cancellation

Made by Ryan with Codex (GPT-6), MIT; upstream SplatJS license copied. Current public source only; frozen R9, product callers, five protocol modules, and all original tests unchanged by this helper.

`gpuMatchAll(feats, pairs, ratio, log, externalDevice, onProgress, { signal, maxPairsPerChunk })` accepts an optional seventh argument. The positive-integer pair ceiling is 1..32767 (two directional jobs per pair), in addition to the existing 96 MB output cap. `runSfM` forwards `opts.signal` and `opts.maxPairsPerChunk`. The product caller must opt into small chunks; no automatic adapter policy was added here. Without the option, existing chunk selection and math are preserved. Empty pair input returns an empty result before device allocation.

Descriptors are uploaded once. Every pair remains in its original position, with both directional jobs kept together. Shader source is byte-identical to the original, SHA-256 e0da9c2eb7c2a0830813efd3593538a031e4d4f39676a0feae6c176c4734c3d1. CPU ratio and cross-check expressions are unchanged. No descriptor, feature, or pair is reduced. Explicit chunking yields to a timer between submissions. Cancellation rejects adapter/device/map waits, prevents later submissions, releases every allocated buffer in finally, and destroys only temporary owned devices. A device arriving after requestDevice cancellation is destroyed when it arrives. Native promises retain rejection handlers.

Pinned Node22 Playwright CPU-only tests use no page/browser fixtures and launch no GPU work. Six initial regressions all failed against original code. After implementation, six passed (8.9 s). Final expanded run on unique port4191: eight passed (6.9 s). Scoped test Prettier and git diff --check passed. Tests emulate only integer descriptor-distance tables on CPU, compare all raw words across default/1/2/4/8-pair chunks, compare returned results to independent matchSift, exercise irregular and repeated pair order, ties and high uint8 descriptors, and verify partial allocation/submission/readback failures, late owned resources, prompt cancellation, signal listener cleanup, event-loop deadline delivery, and real SfM option forwarding without fallback after abort.

This is not real GPU parity, isolated timing, or quality evidence. WebGPU offers no cancellation of an already submitted kernel on an injected device; cancellation releases the wait/resources and stops later chunks. Small chunks bound subsequent work but cannot preempt a current kernel. No claim is made that 4 or 8 pairs meets an end-to-end native deadline on every adapter.
