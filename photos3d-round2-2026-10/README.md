# Photos to 3D — round-two evidence

This directory is prepared for `codex/photos-to-3d-clips`, under `photos3d-round2-2026-10/`. It must never be merged into the product branch. Codex (GPT-6) prepared this evidence.

No acceptance gate is claimed here. The final report and explicit primary run selection determine which measurements support conclusions. See `selection.json`, `audit-report.json`, and `inventory.json`. An initial metadata-only payload intentionally contains no selected primary runs. Exploratory runs, if explicitly selected, remain separate and retain all audit failures. Running receipts are refused.

The real corpus contains three independent captures: AliceVision Buddha, alansartlog's textured die, and alansartlog's skull. Buddha24 and Buddha60 are overlapping selections of the same object capture and count once. Original photographs remain outside git. The synthetic corpus contains three distinct Kenney Food Kit objects rendered with the pinned task 105 renderer: burger-double, cake-birthday, and donut-sprinkles, each with 24 960×720 views and exact cameras. Synthetic views are not real captures.

Standalone image artifacts are limited to mask PNGs and explicitly selected trained-result PNG/PLY files. Beauty/reference RGB inputs, original photos, contact sheets, source GLBs, source textures, source archives, and depth rasters are omitted. One explicit exception is the SHA-pinned preflight failure `verification/preflight-first-failure/trace.zip`, when selected with role `verification-trace`; its graph-plotter UI screenshots and test/resource snapshots are verification evidence, not photo inputs. The curator checks every uncompressed ZIP member against every frozen input-photo SHA-256 and records the member hashes. Arbitrary source archives remain forbidden. The matching `error-context.md` may be selected as `verification-context`. Renderer manifests retain filenames and checksums of deliberately omitted data; those references do not imply that the data is included. There are no vendored code snapshots: source audits link to recorded public Git commits. No network reachability check was performed by curation.

## Protocol

The photo module proposes every unordered pair for 8–60 inputs, canonicalizes identities, reports graph support/components and unplaced views, checks lens metadata, and uses normalized per-photo camera intrinsics. Geometry may use every image's grayscale. Each appearance fold physically excludes the held-out RGB/mask/camera from sparse color rebuilding, surface seeding, trainer targets, loss, and environment fitting, and starts a fresh trainer. The final photo split disables the vendor's additional automatic holdout and blur exclusions. Older receipts retain their recorded implementation; never silently interpret them as later code. In particular, the legacy `ad6ca88f4` B24 phone preview PNGs used canvas readback that returned black, and their appearance training also had an extra automatic split. Those previews are not used for SSIM or appearance acceptance. Their independently computed geometry remains valid. The measured held-out appearance folds use [115f8ee79](https://github.com/ryanjosephkamp/splashery/commit/115f8ee79) and later fixes, which read actual GPU raster output and honor the explicit photo split; each receipt retains its exact source versions.

Real-capture evaluation masks are approximate manual full-object silhouettes placed from input images alone; supports and background openings are excluded conservatively. Full methodology, limitations, source hashes, and normalized polygons remain in each `final-masks.json`. A uniform two-pixel Chebyshev erosion is applied at the annotation scale; stored real mask PNGs already include it. They are evaluation-only annotations, not ground truth and not training inputs. SSIM uses local unweighted 7×7 luma windows entirely within the mask; PSNR uses all masked RGB pixels. Missing, failed, and unregistered views must remain in coverage denominators. Conditional metrics on registered views cannot establish complete-scene acceptance. Synthetic mask PNGs are the renderer's object-index outputs; the manual tracing and erosion procedure applies to real-capture annotations.

Input-photo hashes and each annotation's source-photo identity are checked before browser evaluation. Older probes recorded the annotation-file hash only after completion. The interrupted Buddha LOO200 batch did not reach that write: its recovered receipt has later frozen-mask hash context and supporting pre-run filesystem chronology, which do not prove the exact mask bytes consumed at runtime. That limitation stays attached to its measured folds.

The host-probe changes in [8032fda01](https://github.com/ryanjosephkamp/splashery/commit/8032fda01) hash the exact JSON buffers parsed for annotations, resumed geometry, and camera truth before browser work. For a known frozen dataset, the loaded annotation buffer must match its asset-record SHA-256. These loaded identities are written to the running header and retained in final/browser-error results. [de8ea7238](https://github.com/ryanjosephkamp/splashery/commit/de8ea7238) also retains those identities in pre-browser validation-error receipts. These changes strengthen future receipts; they do not retroactively provide missing hashes for earlier runs. Each selected receipt remains attributable to its own recorded host source.

Software WebGPU, emulated viewport sizes, and brief training probes do not establish physical-phone latency, thermals, peak memory, or full training completion. Exact-correspondence controls bypass image features and do not count as rendered-set benchmarks.

## Reproduction

Run this script from the main source checkout, with the original ignored cache present. It only writes under `.cache/photos3d/round2`. Example:

```sh
python .cache/photos3d/round2/curate-evidence.py --run buddha24-phone-sorted-final --run buddha24-phone-shuffled-final --include-results
python .cache/photos3d/round2/curate-evidence.py --file-list .cache/photos3d/round2/selected-evidence.json
python .cache/photos3d/round2/curate-evidence.py --run <receipt-name> --audit-only
```

A JSON file list accepts `{"primaryRuns":[],"exploratoryRuns":[],"files":[{"path":".cache/photos3d/round2/diagnostics-final.log","role":"verification-log"}]}`. To add the promised graph-plotter failure evidence, append `{"path":".cache/photos3d/round2/preflight-first-failure/trace.zip","role":"verification-trace"}` and optionally `{"path":".cache/photos3d/round2/preflight-first-failure/error-context.md","role":"verification-context"}` to `files`. This trace documents the first preflight attempt only; its inclusion does not assert that a later rerun passed. A plain text list accepts one primary receipt path/name per line. JSON selections also accept explicit `includeResults` and `allowInterrupted` booleans and can be replayed directly. Results are opt-in through `--include-results` or `includeResults: true`. An interrupted derived partial receipt is opt-in through `--allow-interrupted` or `allowInterrupted: true`; enabling this never treats unfinished folds as measured or declares the original running header complete. Existing payloads are moved into `.payload-history/`; all original cache evidence remains untouched.

Raw JSON/checkpoint files larger than 1,000,000 bytes are gzip-compressed with an empty filename and timestamp 0. Original raw receipts and checkpoints are never reformatted. Decompression yields byte-for-byte original content, including original whitespace and numeric spellings. Derived recovery envelopes and generated metadata are separately labeled; they do not replace the raw inputs. Inventory entries record both original and archive SHA-256/byte counts. `inventory.json` cannot hash itself; its own hash is in `inventory.sha256`. Audit errors must be resolved by choosing valid receipts or preserving them explicitly as exploratory; curation never edits raw evidence.

## Interrupted receipt recovery and duplicate accounting

`recover-interrupted.py` creates an explicit derived partial envelope from a saved running header, completed geometry checkpoint, and finished JSONL rows. Original receipts are not rewritten. The recovered envelope retains runtime and geometry-origin provenance, all planned identities, unfinished counts, original artifact SHA-256 values, and exact raw-line hashes. Recovery does not invent total duration, missing scores, or completion. A missing final runtime mask hash remains an explicit limitation; later frozen-mask context and supporting filesystem chronology do not substitute for that missing runtime hash.

Selecting such an envelope as primary additionally requires `--allow-interrupted` (or the explicit JSON selection field `"allowInterrupted": true`). Its original running header is included only as a hashed recovery source, never represented as a completed run. Original JSONL bytes and checkpoint bytes are retained, with deterministic gzip where needed.

The audit's primary-fold ledger deduplicates exact identical raw fold rows by frozen input identities, exact geometry, originating geometry commit, target iterations, resolved profile/tier and seed budget, fixed trainer RNG seed, annotation identity, training/metric source signature, backend, and held-out identity. All duplicate references remain visible. When both explicit sorted/shuffled primary receipts are selected for Buddha24 or Buddha60 at phone or high settings, the audit requires identical frozen input hashes, an actual changed input order, and shuffle seed 104. It compares graph, camera array, point count, and RMS exactly, while excluding timings, progress callback order, and provenance metadata. Pair input/raw hashes and equality results remain in the audit; differences are flagged without changing measurements. Unselected or unfinished companion runs are never discovered automatically. Nonidentical duplicates are errors; no fold is selected by its score. Different training horizons and configurations form distinct experiments. Host-only provenance changes do not split an otherwise identical protocol; the actual host-to-browser option mapping is fingerprinted separately. Each reference retains its actual source hashes and commit. Only the two explicitly listed, statically reviewed evaluator hashes share a training signature: their differences affect fold accounting only; unknown future hashes remain distinct. The recovered batch uses its later frozen annotation hash as grouping context, with the missing runtime-hash caveat retained; grouping does not resolve that limitation.

```sh
python .cache/photos3d/round2/recover-interrupted.py --stem buddha24-phone-loo200
python .cache/photos3d/round2/curate-evidence.py --run buddha24-phone-loo200-recovered --allow-interrupted --audit-only
```
